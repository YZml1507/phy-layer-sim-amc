# 04 信道编码与 Viterbi 译码

> 代码：`src/phylayer/coding.py`
> 验证：`tests/test_coding.py`、exp03 的 coded/uncoded 曲线对比

## 它解决什么问题

再好的调制在噪声里也会出错。信道编码在发送端**加冗余**：把 $k$ 个信息位编成
$n$ 个编码位（码率 $R=k/n$），让接收端能纠正部分错——代价是带宽或速率。

本项目用通信课本的标配：**约束长度 7 的 (2,1,7) 卷积码 + Viterbi 译码 +
分组交织**。这正是 2G~Wi-Fi 时代所有主流系统的编码骨架。

## 原理

### 卷积码 = 有限状态机 + 抽头异或

(2,1,7) 卷积码：一个 6 位移位寄存器 + 当前输入共 7 个抽头位，经过两组生成
多项式 $g_1=171_8, g_2=133_8$（八进制）各异或出一路输出。每进 1 bit 吐 2 bit，
$R=1/2$。64 个状态（$2^{K-1}$）。

发端零尾（zero-tail）：消息后面补 $K-1=6$ 个 0 把寄存器赶回全零态——保证网格
图收尾干净，译码器知道终点状态。

### 交织：打散突发错误

多径衰落信道里错误是**成串**的（深衰落一来连续错一片）。卷积码最怕突发。
交织器把编码比特按"写行读列"重排，解交织后突发错误被**分散**到网格的不同
时刻，各点孤立、Viterbi 可纠。

```python
interleave(bits, rows)   # 写入 rows 行矩阵，按列读出
deinterleave(llr, rows)  # 逆变换；pad 记录补齐的 0 比特数
```

### Viterbi：在网格图上找最可能路径

编码器是状态机 → 所有合法码字对应网格图上一条路径。译码 = 找一条**度量最大**
的路径：

- 硬判决：分支度量 = 接收比特与分支输出比特的**汉明距**（取负）。
- 软判决：分支度量 = $\sum_{i}(1-2g_i)\cdot\mathrm{LLR}_i$——直接把解调器
  输出的 LLR 当证据累加，判决可信度参与度量。

Viterbi 每步对每个状态只保留最优幸存路径（add-compare-select），复杂度与
消息长度**线性**、与状态数 $2^{K-1}$ 成正比——这就是"最大似然序列检测"
的实际算法，复杂度可承受的根源是网格的马尔可夫性。

```python
bits_hat = viterbi_decode(llr, soft=True)   # 软输入：直接用 LLR
bits_hat = viterbi_decode(hard_bits)        # 硬输入：汉明距度量
```

## 实验现象（exp03）

在瑞利 5 抽头 + CFO + AWGN 信道上（QPSK，$E_s/N_0$ 每点 16 帧平均）：

| $E_s/N_0$ | 无编码 | 软 Viterbi |
|---|---|---|
| 10 dB | ~0.06 | ~0.015–0.045 |
| 14 dB+ | ~0.003 | **0**（16 帧全对）|

编码增益清晰可见。低 SNR 端（≤8 dB）同步本身已不可靠，编码救不了帧同步失败
——这是真实的系统行为：**编码纠的是"同步之后的残余错误"，不是万能的**。

## 代码走读

- `conv_encode`：逐比特推进寄存器，输出 $[g_1(b), g_2(b)]$，末尾补 6 个零。
- `_TRELLIS`：一次性预算 64 状态 × 2 输入的 (next_state, out_bits)，译码查表。
- `viterbi_decode(obs, soft)`：前向累积度量 + 幸存者回溯。输入长度应是
  $2(n+6)$，输出 $n$ 个信息位。
- `interleave/deinterleave`：方阵交织，`pad` 记住补了多少零位。

## 面试可能怎么问

- **卷积码的状态数、约束长度、码率？** $K=7$（移位寄存器 6 级+输入），
  $2^{K-1}=64$ 状态，$R=1/2$。生成多项式 171/133 是行业标准的最优自由距码。
- **为什么软判决比硬判决好 ~2dB？** 硬判决把"0.49 的把握"和"0.99 的把握"
  都变成一个比特，丢掉了可信度信息；软判决让 Viterbi 知道哪几位靠不住，
  等效于更准确的度量 → 编码增益更大。
- **交织解决什么问题？能不能不要？** 衰落信道的错误成簇；交织把簇打散成
  孤立错误，匹配卷积码"纠随机错"的能力。不要交织时，深衰落一次就击穿码的
  纠错半径。
- **为什么不用 LDPC/极化码？** 项目要的是"教科书可推导 + 能讲清为什么"，
  卷积码+维特比是编码课的核心；LDPC/Polar 是工程演进方向，面试可主动提
  "同样的软信息框架可以直接换 LDPC 用 BP 译码"作为扩展。
- **译码复杂度随什么指数增长？** 约束长度（状态数 $2^{K-1}$），与消息长度
  线性——这是网格 DP 的本质。
